# Litvak-Tuashi Design

אתר תדמית ופורטל לקוחות לסטודיו לעיצוב פנים של סיגל ליטבק ובן תואשי.

מחליף אפליקציית Base44 קיימת. הרקע וההנמקה ב-[DECISION.md](DECISION.md).

## מבנה

| תיקייה | מה יש בה |
|---|---|
| `web/` | אפליקציית Next.js — האתר הציבורי והפורטל |
| `supabase/` | `schema.sql` — טבלאות, טריגרים ומדיניות RLS |
| `data/base44-export/` | ייצוא CSV של 6 הטבלאות מ-Base44 |
| `content/` | תוכן האתר הישן, עם סימון מה אמיתי ומה placeholder |
| `assets/images/` | 89 צילומי הפרויקטים (מחוץ ל-git — ראו למטה) |

## הרצה מקומית

```bash
cd web && npm install && npm run dev
```

האתר הציבורי עובד ללא Supabase. הפורטל וטופס יצירת הקשר דורשים משתני
סביבה — העתיקו את `web/.env.example` ל-`web/.env.local` ומלאו.

## הקמת Supabase

1. פתחו פרויקט חדש ב-[supabase.com](https://supabase.com).
2. הריצו את `supabase/schema.sql` ב-SQL Editor.
3. Authentication → Providers → הפעילו **Google** ו-**Phone**.
4. Authentication → URL Configuration → הוסיפו את כתובת Vercel כ-Redirect URL,
   עם הנתיב `/auth/callback`.
5. העתיקו URL ו-anon key אל `web/.env.local` ואל משתני הסביבה ב-Vercel.

סיגל ובן מקבלים הרשאת מנהל אוטומטית בכניסה הראשונה — הכתובות שלהן
רשומות בטבלת `admin_emails` ב-`schema.sql`.

## הרשאות

| תפקיד | מה רואה |
|---|---|
| `admin` | כל הפרויקטים, הלקוחות, הספקים, ההזמנות והקבצים |
| `client` | רק הפרויקט שהוא משויך אליו |
| אורח | האתר הציבורי בלבד |

ההפרדה נאכפת ב-Postgres דרך RLS, לא בקוד הצד-לקוח.

## ספריות קבצים

עם יצירת פרויקט נוצרות לו שבע ספריות אוטומטית (טריגר `seed_project_folders`).
המנהל מוסיף, משנה שם, מוחק ומזיז קבצים בין ספריות. הלקוח רואה את כולן, אבל
מעלה קבצים אך ורק דרך ספריית **"העלאות מהלקוח"** — הכלל נאכף ב-RLS ולא בממשק.
כל העלאה של לקוח יוצרת התראה לכל המנהלים.

## ⚠️ תמונות

`assets/images/` מוחרג מ-git בגלל גודלו (154MB), והוא כרגע **הגיבוי המקומי
היחיד** של צילומי העבודות. אין למחוק לפני שהתמונות הועלו ל-Supabase Storage.

האתר מגיש כרגע את התמונות מהאחסון של Base44. לאחר ההעברה — לעדכן את
`IMAGE_BASE` ב-`web/src/lib/portfolio.ts` ואת `next.config.ts`.
